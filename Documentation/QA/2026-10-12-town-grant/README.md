# Town grant API — burn-down item 2

Source-only PR against main; no deploy, production identity or Unity operation. Main missing seam reproduced first in `known-bad.log` (4.569 s). Initial non-emulator invocation refused before any network operation (demo guard); not an API gate. Build/shared parity pass. `townGrantIssue` and `townGrantRevoke` are signed-in pilot callables. `townGrantVerify` is an **Admin SDK check**, intentionally not a Cloud Functions export: an IAM-restricted server process imports it with workload service-account Application Default Credentials. Firebase player tokens never authorize verification. This avoids accepting a client-controlled `holoServer` claim as server identity. Deployment credentials/IAM provisioning and server adapter integration are NOT provided or performed here. `QaAllowlistTownHost` remains the QA instrument until a separately approved deploy/integration.

Contract `town-grant-1`: request schemaVersion/instance; issue returns authenticated uid, instance, `sg_` plus24 lowercase hex characters (96 random bits), expiry120000 ms or instance expiry, whichever earlier. Instance identifier≤64 ASCII identifier bytes; uid≤128. Host registry `townInstances/{instance}` must be enabled with a safe-integer live expiry. No player writes registry. Grant doc key=SHA256 token; only digest stored, no credential/token logging. Unknown fields reject. One current grant per pilot; replacement invalidates older grants. There is no client-selected uid/expiry/nonce.

Server check takes schemaVersion/uid/instance/grant. Atomic first check returns `live`+matching identity/expiry and consumes admission; concurrent/repeated check returns `replay`. Wrong uid/instance returns `foreign` without consumption, expiry returns `expired`; absent/malformed=`invalid`, revoked/replaced/deleted profile/disabled or malformed instance=`revoked`. Revocation is idempotent and owner-bound. Client Firestore reads/writes of grants, pilot index and registry denied by unchanged default rules (6 denied accesses). Account deletion removes index and all owned grant docs, with absent profile failing closed during cleanup.

Integration requirement: socket must disconnect by returned expiry, and the future server adapter must watch the admitted grant + instance/pilot index for revocation/replacement/disable/delete. Revoking a grant changes its record immediately but **this PR does not terminate an existing Unity socket**. No server adapter is installed. Issuance is not yet rate limited; expiry records require operational retention/TTL planning before deploy. Source Admin SDK seam relies on the trusted process boundary; production IAM authentication cannot be witnessed in Firestore emulator. No Firebase custom server token, M3 battle settlement, Unity wire change or credits used.

Tests include anonymous/server-player refusal, foreign uid/instance, expiry boundary, concurrent replay, revoke/replacement, instance disable/malformed expiry, profile deletion and cleanup; player denial controls.
