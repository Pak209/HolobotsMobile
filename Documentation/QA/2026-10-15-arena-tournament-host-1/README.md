## Contract

`tournamentBracketHost`, schema `arena-bracket-1`, accepts `{schemaVersion, operation, matchId}`. Operations are `start`, `resume`, `cancel`, and `advance`; `advance` additionally requires integer `expectedRound` 0–4. Unknown fields (including winner, final HP, opponents, seed, and player UID) refuse `invalid_request`. Authentication supplies the UID.

Admission is the existing paid `arenaMatchHost` issue with `tournamentId`; gathering must have been seen. The owned Holobot thresholds stay **2 / 11 / 21**, independently of pilot rank. Existing entry quotes, **50 / 100 / 150 / 225 Holos** or **1 pass**, are unchanged. New tournament-tagged public Arena start/settle refuse `bracket_required`, including pre-release active admissions. Start binds an issued match and marks it active; ordinary Arena start/settle/cancel then refuse `bracket_bound`. Existing terminal receipt replay remains ahead of these guards, and unbound resume/cancel remain available.

**Explicit shape assumption:** all **8 gathering citizens plus the player = 9 entrants**. A private cryptographic seed selected at binding gives the top **7** byes and a bottom-**2** play-in; the player may be in that pair. The play-in creates the **8-slot** main draw. Four advances resolve **1 / 4 / 2 / 1** bouts respectively, for **8** total receipts and one champion. `round` starts at **0**, reaches **1** after the play-in, then **2 / 3 / 4** after quarterfinals / semifinals / final. No citizen is silently omitted. The refundable issue reply contains no bracket seed. Start draws one unsigned **32-bit** seed outside the Firestore transaction (stable across transaction retries), incorporates it into entrant ordering, then atomically stores/reveals it only with the active, nonrefundable binding. Subsequent rounds/replays are deterministic from that saved seed. Public input cannot choose a seed, preventing predict/cancel/refund outcome shopping.

Each response is `{schemaVersion, matchId, alreadyProcessed, bracket, cancelled}`; a completed player win also returns `storyFlags`. Bracket includes `{schemaVersion, matchId, tournamentId, seed, round, playerAlive, done, entrants, remaining, health, matches}`. Each match exposes its two entrant IDs, winner ID, round, and the W10 `duel-receipt-1` receipt. NPC combat level comes from the original Arena admission's opponent level; own player stats come from its entrant snapshot. All combat and CPU outcomes use the shared resolver's deterministic host policy. Remaining HP carries across rounds; no between-round HP is granted. Each new bout starts STA/SYNC using the shared resolver's existing initial-state policy. Completed receipts are recomputed and validated before stored progress is trusted.

`expectedRound` prevents replay/concurrency from skipping rounds; earlier expected rounds return the current stored result without advancing. A new advance after completion refuses `bracket_done`; a lost player refuses `player_eliminated`; missing/foreign/untagged admissions refuse `not_admitted`. Start/resume allow recovery, and cancel uses host-observed HP, gives no reward/refund after binding, and releases even an expired lease.

The bracket itself grants no intermediate economy. Terminal win/loss uses the admission's existing reward quote once, zero client performance bonuses, final opponent's blueprint identity, and host-resolved HP. The existing Arena helper preserves **5 / 10 / 15 / 20** blueprint counts by tier and the existing XP/sync tables. Resolver round-limit decisions preserve both sides' actual HP through a server-only `bracketWinner` report field rather than inventing a knockout. An ordinary match's validation remains unchanged.

The final win calls existing `transactTournamentResult` unchanged. Settlement/bracket/HP/rewards commit atomically; story progress is its existing separate transaction. If interrupted between them, resume or replayed advance retries progression; `already_won` safely returns current flags. Third win still sets only `arenaArcBuilt`; `holoZonesArcBuilt` is unchanged.
