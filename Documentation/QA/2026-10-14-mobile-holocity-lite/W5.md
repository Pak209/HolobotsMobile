## Account and host behavior review

Rival reads are skipped without a UID and in the offline fixture. The status request has a 15-second deadline; mounted, UID and request-generation checks reject stale async responses after an account change, unmount or newer request. Host observations are keyed by UID, and cooldowns are additionally keyed by pilot. The hook refreshes on navigation focus and app foreground. Logout/locked-session routing unmounts the authenticated navigator.

Cooldowns are presentation observations from confirmed settlement or the host's `retryAfterMs` refusal. The client cannot read the private ledger. Missing or expired observations show an unknown countdown rather than claiming that every rival is eligible. A rematch asks the host again. Holos and roster data still come from the existing profile provider; this skin adds no economy authority.

No critical account-routing or write-authority regression was identified. The review found and fixed a status-freshness race: each UID now has a publication revision captured before a read starts. A newer host publication invalidates that pending read, so neither its late success nor its error replaces the settlement-published state. Existing UID, mounted and request-generation guards remain in force. This focused hook change adds no new test-only interface or renderer dependency; the final combined integration TypeScript check passed.
