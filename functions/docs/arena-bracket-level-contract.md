# Bracket fighter level publication

`tournamentBracketHost` already returns `reply.bracket.entrants[].fighter.level` on main (`f50d028`). This change formalizes and tests that existing host field; it does not add a second level, change runtime behavior, or bump `arena-bracket-1`.

```text
host owned Holobot -> playerCombatant -> arena admission match.entrant.level
host Arena tier    -> match.opponent.level
admitted snapshots -> bracket entrants[].fighter.level -> Unity LV badge mirror
```

The human entry uses the admitted `match.entrant.level`, which comes from the same normalized owned-Holobot combatant as the other host-issued LV displays. Each citizen uses the admitted `match.opponent.level` with its own Holobot stats. These levels are immutable for the bracket, even if the account Holobot levels up after admission. Start, replay, resume, advance and cancel return the stored bracket. Client `level` fields remain `invalid_request`.

| Source | Existing value/rule |
|---|---|
| Human fighter | Admitted owned Holobot level, integer 1–99 |
| Rookie Arena opponents | 12 |
| Challenger Arena opponents | 24 |
| Elite Arena opponents | 36 |
| Legend Arena opponents | 45 |
| Tournament admission thresholds | Starter 2, Champion 11, Rare 21; unchanged |
| Adapter missing input level | `duelFighterFromCombatant` defaults to 1 |
| Missing published reply level | Invalid; no new client default |

The helper default is an input compatibility behavior, not permission to omit a published level. `readArenaBracket` replays the resolver and rejects missing, non-integer, string, null, 0 or >99 levels. This is not `pilotRank`, the Arena tier index, or the tournament admission threshold. No client combat calculation should be added to display it.

`Schemas/arena-bracket-1.json` is deliberately an additive **reply projection** for this field, not a replacement for full host receipt/state validation. Extra existing fields remain accepted. The offline fixture is generated by host `gatheringRoster`, `playerCombatant` and `createArenaBracket`; its deterministic ordering is explicitly fixture-only. The emulator test separately proves actual admission publication with a throwaway pilot, verifies 21 for the human and 12 for all eight Rookie opponents, changes the account to 45 after admission, and verifies unchanged bracket levels through resume and advance.

Regenerate the fixture after `npm --prefix functions run build` with `node functions/scripts/generate-arena-bracket-level-fixture.mjs`. Run `npm --prefix functions test`; the existing emulator suite includes the level test. Both emulator endpoints and project IDs are guarded for loopback `demo-*` only. No production pilot, deploy, credits, Unity code or editor operation is part of this change.
